# 草稿箱

本机未提交稿件的汇总视图：既能同时保留多篇显式草稿，也会把编辑器的自动备份当成草稿列出来。所有副本只写浏览器 IndexedDB，不上传、不包含 PAT，也不进入 Service Worker 缓存。

## 两类本地副本

- **自动备份**（`abs-backups`）：编辑时约 600ms 防抖写入，同一文件只留最新一份，用于意外刷新/关闭后的恢复。**它本身就是一份未提交的草稿**，所以会直接出现在草稿箱里（标记「自动备份」）。
- **显式草稿**（`abs-drafts`）：只在用户点「保存草稿」时写入，同一路径一份，可以同时保存多篇文章。保存草稿不会产生任何 GitHub 写请求。
- 草稿箱按「仓库 + 分支 + 路径」合并两类记录，同一路径只显示一份：保存时间更新的那份胜出。因此打开草稿箱里的条目，永远不会比自动备份更旧。
- 删除草稿箱条目会同时清除该路径的显式草稿与自动备份，避免删掉一份后又从另一份冒出来。
- 自动备份沿用备份存储的上限（最多 20 份，超出时清理最旧的）；想长期保留某篇，点「保存草稿」把它变成显式草稿。

## 保存

- 编辑器文件头的 ghost 按钮「保存草稿」把当前完整状态写入本机：表单/源文件模式、原始 frontmatter、正文、`sourceText` 与已有文件的 `baseSha`。
- 保存成功后底栏显示「草稿箱 HH:mm」，并弹出 toast；文章仍保持「未保存」，盖章才会提交。
- 即使不点「保存草稿」，未保存的编辑也会在约 600ms 后自动备份，并作为「自动备份」条目出现在草稿箱。
- 新建文章先在内存里起草；开始下一篇时，上一篇会先存入草稿箱（优先使用最新编辑器备份，其次已有草稿，最后初始文本），因此可以同时保留多篇新稿。
- 单篇上限约 100 万字符；超出或浏览器存储不可用时不会静默丢弃，会提示清理本机空间。

## 打开与恢复

- 工作台点「草稿箱」把列表切换成本机草稿；每行显示保存时间、标题、路径、新稿/已有文章、自动备份与源文件标记、字数。
- 点一行进入编辑器：显式草稿按保存时的模式恢复表单和正文；自动备份走原来的恢复逻辑。已有文件保留备份/草稿的 `baseSha`，远端在此期间变化时保存会走 409 冲突，不会静默覆盖。
- 若同路径的自动备份比草稿更新（例如打开草稿后又编辑、没再点保存就离开），草稿箱会直接显示更新的备份，打开时优先恢复它。
- 新稿从草稿箱打开时仍走 `new=1`；第一次盖章才创建文件。
- 草稿箱里可以删除单篇草稿（确认后清理本机记录）。

## 加密与存储

- 真实仓库：显式草稿用保险库数据密钥经 HKDF（`abs:draft:v1`，与备份/文章缓存子密钥分离）派生的 AES-GCM 子密钥加密；AAD 绑定仓库/分支/路径、保存时间与大小，换槽复制或篡改都无法解密。自动备份沿用备份信封（`abs:backup:v1`），同样是密文。
- 键含「模式 + 仓库 + 分支 + 路径」，同一路径只保留最新一份。
- 在 DevTools → Application → IndexedDB → `abs-drafts` 中，真实仓库的值是 `v: 1` 信封，搜不到标题、路径与正文。
- demo 模式没有保险库，草稿保持明文。
- 锁定会丢弃内存中的解密草稿；解锁后可重新读取。重置保险库会删除所有真实仓库草稿。

## 清除时机

- 盖章提交成功后：新建稿一定清除；已有文件只有本次会话确实从草稿箱恢复时才清除，避免误删另一份未合并的草稿。
- 移动、删除文章时同步清除该路径草稿。
- 删除草稿箱条目会同时删除该路径的显式草稿与自动备份；重置保险库、清除站点数据会删除对应记录。

## 限制

- 只在本机，不同步到其他设备或浏览器；换浏览器/清站点数据会丢失。
- 同一路径只保留一份草稿，后保存的覆盖前一份。
- 草稿不包含图片等附件；只保存 Markdown/MDX 文本与 frontmatter。
- 已有文件的远端被删除后，草稿仍存在但需要恢复文件才能再次保存。
