# 未保存备份

编辑器的本机草稿恢复。备份只写浏览器 IndexedDB，不上传、不包含 PAT，也不进入 Service Worker 缓存。

## 开关与范围

- 设置里可关闭或清除本仓库备份。
- 编辑器只在本机保存最新一份草稿，按「模式 + 仓库 + 分支 + 路径」隔离；同一文件多次编辑只保留最后一次。
- 真实仓库的备份是密文，demo 仓库没有保险库，备份保持明文。

## 写入时机

- 编辑时约 600ms 防抖把整份文件快照写入本机 IndexedDB。
- 底栏在「未保存」旁显示「本机已备份 HH:mm」。
- 多标签页编辑同一文件时，后写入的备份胜出，不做合并。

## 加密与存储

- 真实仓库：整份草稿（正文 + frontmatter + 恢复状态）用保险库数据密钥经 HKDF 派生的 AES-GCM 子密钥加密后写入本机 IndexedDB；明文只存在于内存。
- 键含模式/仓库/分支/路径；仓库/分支/路径与保存时间仍作为索引元数据明文。
- 不包含 PAT，不上传，也不进入 Service Worker 缓存。
- 在 DevTools → Application → IndexedDB → `abs-backups` 中，值是 `v: 2` 信封，搜不到文章标题/正文。
- demo 模式没有保险库，备份为明文。
- 锁定后读不到备份。

## 恢复流程

- 进入编辑器时只检查一次：有备份就弹 `AlertDialog`，显示保存时间、字数、路径；远端已变化会额外提示，没有就正常打开。再次进入同一文件（含刷新后的 `new=1` 新稿）也会检查备份。
- 操作为「稍后 / 丢弃备份 / 恢复备份」。
- 选择「稍后」会保留备份并在文件头显示恢复条；这期间自动备份暂停，避免覆盖旧草稿。
- 选中「恢复备份」后：恢复已有文件保留备份里的 blob sha，保存仍走 409 冲突；恢复新稿回到「未提交」，首次保存前不写仓库。
- 表单与源文件模式的备份都能恢复。

## 清除时机

- 保存、移动、删除成功后自动清除对应备份。
- 锁定前会先把当前草稿 flush 成本机加密备份，再清空密钥。
- 重置保险库会删除本机所有真实仓库备份；浏览器清站点数据也会一并清除。
- 设置里可以关闭备份或清除本仓库备份。

## 限制

- 备份只在本机：真实仓库的备份是密文、只能在解锁后读取；换设备/换浏览器不会同步。
- 同一文件多标签页编辑时最后写入者胜出，不做合并。
- 锁定后读不到备份；重置保险库或清除站点数据会一并清除。

## 测试与边界

- 单元测试覆盖：备份记录校验、整文件快照、恢复映射、IndexedDB 上限、防抖与卸载清理、锁定前 flush、备份加密信封/篡改/换槽/锁定拒写/旧明文迁移。
- 手动验证步骤见 [testing.md](testing.md) 的第 9–10 条。
