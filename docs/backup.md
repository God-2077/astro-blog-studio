# 未保存草稿（自动保存）

编辑器在编辑过程中自动保存的本机草稿。它只写浏览器 IndexedDB（实现目录仍叫 `lib/backup`，存储键 `abs-backups`），不上传、不包含 PAT，也不进入 Service Worker 缓存。它和显式草稿一起出现在工作台「草稿箱」里。

## 开关与范围

- 设置里可关闭自动保存，或清除本仓库所有分支的本机草稿（显式草稿 + 自动保存记录）。
- 编辑器只在每台设备保存最新一份草稿，按「模式 + 仓库 + 分支 + 路径」隔离；同一文件多次编辑只保留最后一次。
- 切换仓库不会删除其他仓库的草稿；切回后进入同一文件仍会检查并恢复该仓库的草稿。
- 真实仓库的草稿是密文，demo 仓库没有保险库，草稿保持明文。

## 写入时机

- 编辑时约 600ms 防抖把整份文件快照写入本机 IndexedDB。
- 底栏在「未保存」旁显示「本机草稿已保存 HH:mm」。
- 多标签页编辑同一文件时，后写入的草稿胜出，不做合并。
- 普通打开的文章不显示「保存草稿」按钮；从草稿箱打开的会话才提供手动保存，用于在自动保存之外立即落一份显式草稿。

## 加密与存储

- 真实仓库：整份草稿（正文 + frontmatter + 恢复状态）用保险库数据密钥经 HKDF 派生的 AES-GCM 子密钥加密后写入本机 IndexedDB；明文只存在于内存。
- 键含模式/仓库/分支/路径；仓库/分支/路径与保存时间仍作为索引元数据明文。
- 不包含 PAT，不上传，也不进入 Service Worker 缓存。
- 在 DevTools → Application → IndexedDB → `abs-backups` 中，值是 `v: 2` 信封，搜不到文章标题/正文。
- demo 模式没有保险库，草稿为明文。
- 锁定后读不到草稿。

## 恢复流程

- 进入编辑器时只检查一次：有草稿就弹 `AlertDialog`「发现未保存的草稿」，显示保存时间、字数、路径；远端已变化会额外提示，没有就正常打开。再次进入同一文件（含刷新后的 `new=1` 新稿）也会检查草稿。
- 操作为「稍后 / 丢弃草稿 / 恢复草稿」。
- 选择「稍后」会保留草稿并在文件头显示恢复条；这期间自动保存暂停，避免覆盖旧内容。
- 选中「恢复草稿」后：恢复已有文件保留草稿里的 blob sha，保存仍走 409 冲突；恢复新稿回到「未提交」，首次保存前不写仓库。
- 选择「丢弃草稿」会同时删除该路径的显式草稿与自动保存记录，草稿箱里也不会再出现；刷新后不再提示。
- 表单与源文件模式的草稿都能恢复；非 `.md` / `.mdx` 文件一律按整份纯文本恢复（不解析 frontmatter）。

## 清除时机

- 保存、移动、删除成功后自动清除对应草稿。
- 锁定前会先把当前草稿 flush 成本机加密草稿，再清空密钥。
- 重置保险库会删除本机所有真实仓库草稿；浏览器清站点数据也会一并清除。
- 设置里可以关闭自动保存，或清除本仓库所有分支的本机草稿（显式草稿 + 自动保存）。

## 限制

- 草稿只在本机：真实仓库的草稿是密文、只能在解锁后读取；换设备/换浏览器不会同步。
- 同一文件多标签页编辑时最后写入者胜出，不做合并。
- 锁定后读不到草稿；重置保险库或清除站点数据会一并清除。

## 测试与边界

- 单元测试覆盖：草稿记录校验、整文件快照、恢复映射、IndexedDB 上限、防抖与卸载清理、锁定前 flush、AES-GCM 信封/篡改/换槽/锁定拒写/旧明文迁移。
