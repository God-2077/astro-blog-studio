# 本机文章缓存与增量同步

Dashboard 的文章列表来自本机加密缓存：首次打开全量读取，之后按 HEAD 文件树做增量比对，未变化的仓库不重新请求文章内容。

## 首次全量

- 首次打开用 GraphQL 按 **20 篇 / 批**把全库文章读一遍。
- 同时读取 HEAD 文件树，记录 tree sha + 路径/blob sha。
- 文章与索引 meta 用保险库数据密钥经 HKDF 派生的 AES-GCM 子密钥加密后写入本机 IndexedDB。
- 超过 1000 篇时只缓存前 1000 篇并提示。

## 增量规则

- 每次打开只拉一次 HEAD 文件树。
- 只在 HEAD 树 → 新增；同路径 blob sha 不同 → 修改；只在缓存 → 删除。
- 只重新读取新增/修改的文章，并从缓存删除已删除的文章。
- 未变化的仓库 **0 次文章内容请求**。
- 文件树被截断（truncated）时跳过删除，避免误删缓存。
- 失败的批次可重试；强制全量会清除缓存后重新读取。
- 所有 GitHub 请求在 fetch 层使用 `cache: 'no-store'`；GitHub API 的 `Cache-Control: max-age=60` 不会让「检查更新」或刷新读到旧 tree/blob。

## 加密与存储

- 索引 meta（tree sha + 路径/blob sha）和每篇文章（路径 + sha + 正文）分别用保险库数据密钥经 HKDF 派生的 AES-GCM 子密钥加密后写在本机 IndexedDB `abs-content`。
- DevTools → Application → IndexedDB → `abs-content` 中只有 `v: 1` 信封，搜不到标题/正文。
- AAD 绑定仓库/分支/路径/blob sha，换仓库或换 sha 都解不开。
- 锁定会清空内存中的明文摘要；重置保险库会删除本机所有 `live:` 文章缓存。
- 缓存不进 CacheStorage，也不含 PAT。
- demo 仓库只在内存里缓存，刷新回到 fixture。

## 上限、降级与并发

- GraphQL 不可用时回退 Contents REST。
- 并发数由设置里的「索引并发」控制（**1–10，默认 3**）。
- 写入失败（例如配额不足）只降级为内存会话并提示，不阻塞浏览。
- 失败批次、截断、配置签名变化、强制全量等边界都有单元测试覆盖，见 [testing.md](testing.md)。

## Dashboard 与设置

- Dashboard 顶部显示「首次加载 / 正在检查远端更新 / 正在同步文章」进度与「检查更新」按钮，设置里有「强制全量更新」。
- 检查更新进行中：按钮立即禁用并显示「检查中… / 同步中…」，状态条显示「正在检查远端更新…」，顶部 loading toast 持续到结果返回后替换为成功/失败；索引卡刷新按钮同步旋转。
- 「最近动过」、草稿与加密计数仍基于全库，排序依据是 frontmatter 的 `updated` / `date`。
- 「最近动过」可切换 `updated` / `date` 排序；列表下方「加载更多」每次追加 20 篇，到底显示「已全部显示 N 篇」。

## 配置变化与多标签页

- 缓存按「设备 + 浏览器 + 仓库 + 分支 + 内容配置」独立；修改根目录/扩展名/排除规则后，首次打开会重新全量读取。
- 多标签页各自同步，最后写入的 meta 胜出（最坏多读几次，不会损坏数据）。

## 离线限制

- 离线只缓存前端：断网能打开界面，已缓存的文章列表仍可见。
- 但 HEAD 文件树、编辑器正文与提交仍要连 `api.github.com`；未保存备份能在本机恢复，但断网刷新后仍无法读取文件正文，不是完整的离线编辑；没有离线保存队列。
